# Fridge Rescue AI supervised ranking update
Back up app.py and engine.py, extract into project root. Keep ingredient_names.py and recipes_foodcom.csv from the previous update. Run `python train_models.py --train-queries 1000 --test-queries 300 --seed 42` using your existing virtual environment. Then run `python -m streamlit run app.py`. Models appear for the matching Food.com dataset only. Only load the model artifact generated locally; joblib uses pickle. Do not share untrusted model artifacts.

The model learns synthetic target retrieval, not real user preferences. Training targets and test targets are disjoint random recipe rows; the full catalog is indexed in both stages (transductive retrieval). Training negatives are unlabeled candidates sampled from the training partition. Historical rating features use only interactions_train.csv, excluding zero ratings. These ratings are recipe-level popularity signals, not pantry labels. Test queries sample target recipes with replacement, so query bootstrap intervals are descriptive conditional on the catalog and protocol. No hyperparameter tuning or independent human judgments yet. Do not tune on the test set. The model scores are not calibrated probabilities of cooking feasibility. Report missing ingredients and utilization as proxies, not actual food waste or shopping convenience. No dataset included. Outputs are in ml_results. Dependencies already installed by requirements.txt (joblib is a scikit-learn dependency).
